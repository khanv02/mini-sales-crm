# Checklist — Security Review

Run before every release/M2, and for any feature with auth, webhook, file upload or AI.

## Auth & session

- [ ] Access token is short-lived (15m), refresh rotates, reuse revokes the family.
- [ ] Refresh cookie is HttpOnly/Secure/SameSite; never in localStorage.
- [ ] Logout revokes; inactive users are blocked from refreshing.
- [ ] Login rate limit is 5/15m; responses never reveal whether an email exists.
- [ ] Argon2id/bcrypt cost is sufficient; hashes never logged.
- [ ] JWT secret is strong, has no default, and rotation is planned.

## Tenant & RBAC

- [ ] Every business table has `org_id`; composite FK present.
- [ ] Every query filters by org; no `findUnique({id})` for business data.
- [ ] Test org B → 404 for every endpoint.
- [ ] Sales cannot read/modify other users' data; realtime rooms are correct.
- [ ] An Admin of org B cannot manage org A.
- [ ] `orgId/userId/role` are never trusted from the client.

## Input/output

- [ ] zod/DTO validation; length/body/file limits enforced.
- [ ] Uniform error shape; no stack/SQL/secret leakage.
- [ ] XSS: text is rendered escaped; no `dangerouslySetInnerHTML` with user data.
- [ ] SQL injection: Prisma/parameterised queries; raw SQL always filters by org.
- [ ] CSV injection: escape `= + - @ \t \r`.
- [ ] SSRF: never fetch a user-supplied URL; the AI provider URL is configured.
- [ ] Path traversal: storage keys are generated by the server.

## Webhook

- [ ] HMAC over the raw body + timestamp; timing-safe; replay window 300s.
- [ ] Secret encrypted with AES-GCM; never logged or returned; rotation has a grace period.
- [ ] Idempotency key is unique; body limit enforced; an inactive source returns 401.
- [ ] Retries are bounded; DLQ in place; no duplicate records.

## File upload/import

- [ ] Size/row/type limits; streaming; no automatic decompression.
- [ ] Files stored outside the web root; short-lived signed URLs.
- [ ] File contents are never logged; temporary files are deleted.
- [ ] Org/role checked before reading a job.

## Cache & rate limit

- [ ] Cache keys include org + role/user; no data leakage.
- [ ] Invalidation happens after commit; Redis failures bypass safely.
- [ ] Rate limiting fails closed for auth/webhook; headers are correct.

## AI

- [ ] Only the current org's data is sent; email/phone masked.
- [ ] Prompt injection: delimiters + fixed system prompt; no tool calls.
- [ ] Prompts/responses are not logged in full; the API key is never logged.
- [ ] Quota is checked before the provider call; usage recorded fully; no cross-org cache.
- [ ] Output validated (score 0–100/JSON); rendered safely.

## Infrastructure & dependencies

- [ ] Helmet, CORS whitelist, body limit.
- [ ] Secret scan in CI; `pnpm audit` has no unresolved critical issues.
- [ ] Sentry carries no PII/secret; `sendDefaultPii=false`.
- [ ] Log redaction is tested.
- [ ] Backup/restore has been rehearsed; migration rollback exists.

## Conclusion

- [ ] No open Critical/High findings.
- [ ] Every Medium has an owner and a target date.
- [ ] Residual risks are recorded in the PR/release notes.
